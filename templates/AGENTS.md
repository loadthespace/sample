# AGENTS.md

## 목표
- AGREEMENT.md의 성공 기준을 만족하는 최소 기능을 만든다

## 사람(나)이 결정하는 것 — AI는 제안만 한다
- 어떤 방향으로 갈 건지와 지켜야 할 기준은 무조건 내가 정의한다
- 어떤 문제를 해결해야 하고, 무엇을 중요하게 여기는지는 모두 나의 컨펌으로 정한다. 임의로 생각하지 말 것
- 범위와 우선순위
- 판정·집계 기준과 숫자 정의
- 제안에 대한 승인

## AI가 반드시 할 것
1. 판단마다 근거(파일·행·담당자 발언)를 댄다. 없으면 "확인 필요"라고 쓴다
2. 모르는 내용은 모른다고 말하고, 추측일 경우 앞에 "추측"을 넣는다
3. 불확실하거나 명확하지 않은 데이터는 내 요청에서 벗어난 범위에서 임의로 찾거나 생성해서 넣지 말고, 이와 관련하여 나에게 물어본다
4. 수정 전에 범위와 영향을 먼저 말한다
5. 작업이 끝나면 검증 방법과 결과를 보고한다
6. 웹 서버는 0.0.0.0, 포트 8000으로 실행한다
    - 서버는 서버 담당 세션 하나만 켠다. 다른 세션은 서버를 새로 켜지 말고 이미 켜진 localhost:8000으로 확인한다
7. 커밋은 요청받았을 때, 작은 단위로 한다. 커밋 전에 바뀐 파일 목록을 보여 준다. 메시지 형식:
    - feat: 새 기능 / fix: 무엇을 (어떻게 발견) / docs: 문서 / refactor: 구조 정리 / revert: AGENTS 규칙 위반 - 무엇 제거
    - 태그는 요청받았을 때 붙인다: 최초 완성 구현은 v0, 검증 후 수정판은 v1, v2, v3 순서
    - 커밋했다면 답변에 직전 커밋과 이번 커밋(번호·메시지)을 함께 쓰고, 바뀐 내용을 요약한다

## AI가 절대 하지 말 것
1. 제공받은 자료 원본 수정 (필요하면 수정하기 전에 사람(나)에게 물어볼 것)
2. AGREEMENT.md에 없는 기능·구조·라이브러리 추가 (필요하면 이유를 먼저 말하고 승인받기)
3. 실행하지 않고 "완료/통과"라고 말하기
4. 비밀값(API 키 등)을 코드나 커밋에 넣기
5. 요청 범위 밖 파일 수정, 테스트 삭제·약화로 통과시키기
